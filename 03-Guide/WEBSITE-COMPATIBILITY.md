# Automatic Migaku parsing in comic overlays: compatibility audit

Tested 3 November 2026 in installed Google Chrome, OCR Companion for Migaku experimental 1.5.4, Migaku Early Access 1.32.0-earlyaccess.3, existing native macOS Apple Vision helper. Frozen release 1.5.3 is unchanged. This is a separate check from the [OCR compatibility audit](EARLIER-COMPATIBILITY-AUDIT.md) and [earlier regression sweep](EARLIER-OCR-REGRESSION.md).

## Scope and interpretation

All 55 requested website entries are accounted for below. 37 entries received fresh reader attempts in this sweep (Baozi/Twmanga share one actual chapter); Bilibili and Kuaikan use earlier live evidence from the same 1.5.4 experiment. The remaining 16 retain prior unavailable/blocked evidence and were not freshly retried. Bookwalker was tested on its public trial host, Bilibili on its manga host. This does not verify their other hosts.

Working means actual comic narration/dialogue was OCRed locally and Migaku automatically annotated it in the comic overlay, without Shift to trigger parsing. Partial means automatic parsing was observed but the sample was cover/notice-only, crop/accuracy was inadequate, or the requested host remains unverified. Unavailable means no usable comic sample could be tested; it does not prove the extension fails. No site is classified Unsupported without evidence of an actual pipeline failure.

Full power must be enabled **for the site and selected learning language**. Several sites initially had Migaku disabled; enabling it resolved parsing without an adapter change. Japanese, Korean and English were initialized with Manual → Skip import, zero known words, as explicitly authorized. Mandarin was restored afterwards with its existing 2,605 known words, and OCR preference restored to Simplified Chinese. Zero-known profiles verify automatic unknown-word markings/segmentation; they do not verify mixed known/unknown classification as thoroughly as Mandarin. No vocabulary was deliberately marked known for testing.

The OCR completion message precedes Migaku’s asynchronous annotation: a fresh result may briefly appear as plain text. Completed parsing was checked separately where necessary. Screenshots, accessibility snapshots and attempt logs are retained under `work/migaku-site-audit/`; reviewed-results.json is the canonical human-reviewed outcome, while results.json contains raw, sometimes repeated/incomplete attempts. Neither URL matching nor recognition of a catalogue, error or notice counts as a dialogue pass.

Normal browser zoom/Retina display only in this sweep; this is not new zoom/high-DPI/spatial-coordinate regression coverage. The overlay is a reading panel, not word boxes aligned to speech bubbles. No additional host permission, OCR dependency, source adapter or Mac binary change was made during this sweep. Bilibili continues to use the previously approved optional exact-host compatibility bootstrap.

## Findings and recommended follow-up

1. **Keep generic support.** Automatic parsing worked across source images, canvas crops and generic screenshots without adding per-site Migaku shims. Bilibili remains the isolated exception due to Migaku’s site-specific parse-root selection.
2. **P0, small capture cleanup:** temporarily hide Migaku’s own toolbar root during screenshot capture and restore it exactly afterwards. Generic captures on several sites OCRed vocabulary counts/comprehension UI. Manual area selection is the existing workaround. This is a recommendation, not an implemented fix in 1.5.4.
3. **P0, moderate crop improvement:** select both visible comic canvases or expose a predictable spread choice. Shonen Jump+ initially cropped the blank/title half instead of dialogue. Native page turn produced a verified pass, but does not fix the missed half. Add geometry tests before changing shared reader bounds.
4. **P1, small/moderate UI cleanup:** keep generic panel controls outside Migaku’s parsing scope if an officially supported exclusion mechanism can be established. On English sites, Migaku annotated dropdown labels, buttons and explanatory text as well as OCR output. Bilibili’s text-only root avoids this there. Do not invent a universal private Migaku API or suppress parsing of recognized text.
5. **P1, testing:** revisit cover/advert-only samples (Kuaikan, Manben, Creative Comic, Manhuahao, Dumanwu, Comic Days, Kurage), establish longer Kakao Page/Toomics dialogue, and clean dialogue samples for Manga Plus, Tapas and INKR. Retry ebookjapan when its public preview is usable. Match Traditional Chinese OCR explicitly for accuracy testing.
6. **P2, environment-dependent:** remaining region/login/unavailable readers require an accessible public sample or tester in a supported environment. No region gates, safety blocks, paid access or login requirements were bypassed.

## Limits of interoperability

This verifies one installed Migaku version and one Mac, not a supported Migaku integration contract or universal website support. Recognition quality still depends on font size, vertical lettering, artwork and chosen crop. No full-catalogue, full-chapter, paid-content, offline, vocabulary-status-change synchronization, alternate browser or second-Mac test was performed. The existing Shift dictionary lookup and optional separate reader remain fallbacks. The external reader was not made mandatory.

This audit changed test settings and documentation only. Existing automated test results for the implementation remain in [the experiment report](MIGAKU-INTEGRATION.md); no new executable change was made requiring a new build. The frozen shareable app and documentation archive were not modified.
